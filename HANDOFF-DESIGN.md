# PlayReps: что есть и что оформлять

Для того, кто делает дизайн. Логика готова и покрыта тестами. Экраны сейчас черновые: их можно
переписать целиком.

## 1. Запуск

```bash
npm install
```

```bash
npm run dev
```

Открыть http://localhost:3000. Проверка после правок: `npm test`, `npm run typecheck`, `npm run build`.

## 2. Что можно менять и что нельзя

- **Можно всё:** `app/globals.css`, `components/`, разметка страниц в `app/`, шрифты в `app/layout.tsx`.
- **Не трогать:** `lib/`, `hooks/`, `client/`, `app/api/`. Там правила, счёт, реакции Мии, голос, оплата.
- Экран ничего не считает. Он берёт данные из хука и вызывает его действия. Образец: `components/RoundStage.tsx`.
- Тексты тренера, уроков, плана и подсказок голоса приходят из `lib/`. Их менять только вместе со мной.
- Каждая страница в `app/` обёрнута в компонент с `key={bfcacheId}` (первые строки файла). Обёртку
  не убирать: без неё ссылка на пройденную страницу показывает её старый последний экран.
- Next.js 16: страницы начинаются с `'use client'`; во время отрисовки нельзя вызывать `Date.now()`,
  `new Date()`, `Math.random()`; `window` и `localStorage` читать только в `useEffect`.

## 3. Кто смотрит и на чём

- Родитель из США, 25–45 лет, с телефона. Одна колонка, сейчас `max-w-[460px]`.
- Жюри смотрит с ноутбука около трёх минут, без входа. Порядок: `/` → `/play` → `/dashboard` → `/pricing`.

## 4. Экраны

| Адрес | Что это | Состояния |
|---|---|---|
| `/` | Мия говорит первой, родитель отвечает | до ответа; после ответа (разбор фразы, просьба повторить её слова, кнопка на раунд) |
| `/play` | Первый визит | правила; раунд 1 (60 с); итог 1; урок; раунд 2 (40 с); было и стало; 1 вопрос; план |
| `/play?daily=1` | Ежедневные 5 минут | старт; раунд; итог |
| `/live` | 5 минут с настоящим ребёнком, голосом (бета) | инструкция; сессия; итог |
| `/dashboard` | План, серия дней, навык, отметка об истериках, демо | загрузка; пусто; с данными; демо-режим |
| `/pricing` | Пейвол, два тарифа, тестовая оплата Stripe | обычное; идёт переход; ошибка с демо-разблокировкой; вернулся без оплаты |
| `/unlocked` | Возврат из Stripe | проверяем; оплачено; не оплачено |
| `/jury` | Памятка для жюри | одна страница |

## 5. Экран раунда: главный экран продукта

Файл `components/RoundStage.tsx`. Данные из `useRound()`. Что на нём есть сверху вниз:

1. Заголовок раунда, сколько секунд осталось, полоска времени.
2. Сцена с Мией: подпись «Simulated child», сама Мия (лицо и поза), что она делает, что говорит,
   строка мгновенной реакции на последнюю фразу родителя.
3. Три полоски: Connection, Focus, Talking (0–100).
4. Три кольца «сколько из скольких»: Praise, Reflect, Describe. Кольцо заполнено: момент радости.
5. Лоток «To swap»: счётчик вопросов, команд и замечаний. Спокойный, без красного.
6. Реплика тренера: одна строка, может быть пусто.
7. Поле ввода и кнопка «Say».
8. Голос: кнопка «Speak instead» / «Stop listening», галочка «Coach speaks aloud», строка «Listening: …»
   со словами на лету, подсказка про паузы, строка о приватности, сообщение об ошибке микрофона.
9. Кнопки «Copy her (no words)», «Wait quietly», «End round».
10. Последние три фразы родителя: текст, цветная метка категории, ссылка «Disagree?».

В живом режиме (`/live`) пунктов 2, 3 и кнопок Copy/Wait нет, колец два, вместо сцены абзац,
текст которого зависит от микрофона.

**Проблема для телефона:** экран выше одного экрана. Когда открыта клавиатура, Мия и кольца
уезжают вверх, и родитель не видит реакцию на свою фразу. Нужна компоновка, где Мия, кольца и поле
ввода видны одновременно над клавиатурой.

## 6. Мия

`components/Mia.tsx`, рисунок в SVG. Нужны все сочетания:

- Лица: `beaming`, `smiling`, `neutral`, `pouting`, `crying`.
- Позы: `leaning_in`, `at_toy`, `turned_away`.
- Две сцены: кубики и рисование (`lib/child/scenes.ts`).

## 7. Категории фраз и цвета

| Категория | Сейчас | Куда идёт |
|---|---|---|
| Specific praise | жёлтый `sun` | кольцо Praise |
| Reflection | синий `sky` | кольцо Reflect |
| Description | зелёный `leaf` | кольцо Describe |
| General praise, Neutral, Not coded | светлый | никуда |
| Question, Command, Criticism | песочный `sand` | лоток «To swap» |

Палитра и классы описаны в `DESIGN.md` и в начале `app/globals.css`.

## 8. Правила, которые нельзя нарушать

- Никакого красного для «плохих» фраз и никаких слов wrong, bad, mistake, should, don't.
- Подписи обязательны: «Simulated child» у Мии, метка демо у симулированной семьи, «Test mode» у оплаты,
  нижняя строка «Not therapy and not a diagnosis».
- Цена, срок продления и дата продления стоят рядом с кнопкой оплаты. Про отмену ничего не пишем:
  кнопки отмены нет.
- Никаких обещаний про поведение ребёнка.

## 9. Состояния, которые легко забыть

- Панель без данных и панель до чтения с устройства.
- Reflect на панели может быть «не измерено» (после живой сессии): прочерк и подпись, не 0%.
- Микрофон отклонён, не поддерживается, выключен.
- Фраза на другом языке: метка «Not coded». Оспоренная фраза: зачёркнута, ссылка «Count it».
- Лоток «To swap» сверх нормы: чуть темнее, без тревоги.
- Ошибка оплаты и демо-разблокировка.

## 10. Где дизайн важнее всего

1. Экран раунда: Мия, кольца, тренер.
2. Первый экран `/`: фраза Мии и разбор ответа.
3. «Было и стало» после второго раунда.
4. Панель и демо «месяц за 30 секунд».
5. Пейвол.

Подробности логики: `ARCHITECTURE.md`.
